# Changelog

## Unreleased

Changes relative to the previous version, microsoft/nxmndr `main` at commit `f0463ee` (later commits there change only dependency versions and the README's demo image). Every "was" describes that version.

### Breaking changes

Server and proxy:
- The gRPC server binds 127.0.0.1 by default (was every interface, `[::]`), and `nxmndr-server --host` now sets the gRPC address as well as the HTTP proxy's; an IPv6 address may be given with or without brackets (`::` or `[::]`). Operator: pass `--host 0.0.0.0` to accept other machines, after reading [Security](README.md#security).
- The HTTP proxy (`nxmndr-server --azure-proxy`, `python -m nxmndr server`, `python -m nxmndr.server.azure_openai_proxy`) binds 127.0.0.1 by default (was 0.0.0.0). `python -m nxmndr grpc` gains `--host`. Operator: pass `--host 0.0.0.0` to accept other machines.
- When its `stop_event` is set, `serve` stops the gRPC server with a grace of `stop_grace` seconds (default 5): running RPCs get that long to finish, and the model cache then waits at most as long again for running predictions before it frees the models (was: a grace of 0 s, so running RPCs were cancelled at once). Embedder: pass `stop_grace=0` to cancel running RPCs at once.

Model loading (`LoadModel`, `UnloadModel`):
- `LoadModel` with a spec equal to that of a loaded model returns that model's `model_id` (`effective_metadata` has `model_cache_hit=true`) and loads no second copy; a local file or directory `source` is loaded again after its size or modification time on the server host changes. `UnloadModel` releases one `LoadModel` reference, also while a session or call uses the model. When no reference is left, the model is freed at once if no session or call uses it, and otherwise as soon as the last session or call that uses it ends, unless a `LoadModel` takes a new reference first (was: every `LoadModel` returned a new `model_id`. For an ONNX or Hugging Face spec it loaded a new copy, and `UnloadModel` removed that copy at once, also while a session or call used it. For a PyTorch spec it loaded nothing in the server: the first one started the PyTorch RPC worker, which loaded only that spec's model, and `Predict` and stream tiles with any PyTorch `model_id` ran that one model, because the call named no model; `UnloadModel` removed the `model_id` and left the worker's model loaded). A `LoadModel` whose client is gone when the load finishes (its deadline passed or it cancelled) keeps no reference and frees nothing: the model stays cached until it is evicted, as one that only sessions loaded does. One that its client gives up on after that moment keeps its reference. Client: call `UnloadModel` once for each successful `LoadModel`.
- The server keeps at most `NXMNDR_MODEL_CACHE_CAPACITY` models (default 10). A new model at full capacity evicts the least recently used model that no session or call uses, also one whose `LoadModel` callers have not unloaded it, and `Predict` with its `model_id` then fails with `NOT_FOUND`. If every loaded model is in use, `LoadModel` fails with `RESOURCE_EXHAUSTED` (was: models stayed loaded until `UnloadModel`). Client: on `NOT_FOUND` call `LoadModel` again, or run tiles through a session (`OpenSession`), which keeps its model loaded until the session closes.
- `LoadModel` with `overwrite=true` fails with `FAILED_PRECONDITION` while a session, a running call or an earlier `LoadModel` caller holds the loaded model (was: `overwrite` was ignored, and every `LoadModel` returned a new `model_id`). Client: unload your own `model_id` first; the next `LoadModel` then loads a new copy unless another caller, a session or a running call still holds the model.
- `LoadModel` and `OpenSession` refuse a non-empty `ModelSpec.preprocessing` or `ModelSpec.postprocessing` with `INVALID_ARGUMENT` (was: ignored). Client: send empty lists and build the preprocessing into the exported model.
- `ModelManager.load_spec`, `ModelManager.get_model_for_device` and `ModelManager.register_temp_artifact` are removed (was: `load_spec` loaded a spec under a new `model_id`, `get_model_for_device` returned the model's copy for a device, and `register_temp_artifact` listed a file to delete when no ONNX model was left). Embedder: load with `ModelManager.load(model_spec, key=cache_key_from_spec(...))`, which returns a `LoadResult` with the `model_id`; for a call, take an `ExecutionLease` with `acquire_execution(model_id=...)`, use its `model_for_device(device_id)`, and release the lease when the call ends.

Sessions and streaming (`OpenSession`, `StreamPredict`, `CloseSession`, `CancelSession`):
- Every message of a `StreamPredict` tile carries `context["tile_id"]`; a message without it ends the stream with the stream-scope error `missing_tile_id` (was: not required). An `end_of_sequence` message with no chunk and no `tile_id` still ends the open tile. Client: set `tile_id` on every message (`InferenceGrpcClient.stream_predict` does).
- Per-tile options are read only from `context["opt.<name>"]` on the tile's first message (was: every context key of the tile's first message with a context was an option). Other context keys, apart from `session_id` and `tile_id`, are ignored, and the server logs each such key name once per stream at WARNING. Client: rename `key` to `opt.key` on the tile, or send session-wide options without the prefix in `OpenSessionRequest.options`.
- A segmentation tile returns the mask alone (`payload_format` `raw`); mask and confidence come as a tensor bundle only with the option `return_confidence=true` (was: a stream always returned the bundle with confidence). Client: send `opt.return_confidence=true` on the tile, or `return_confidence=true` in `OpenSessionRequest.options`.
- `batch_size`, as a context key or a session option, no longer batches tiles: the server runs the tiles of a stream one at a time in arrival order (was: a `batch_size` context key on the stream's first message ran its tiles in batches of that size). Client: remove it, and keep several tiles in flight with `transport.max_inflight`.
- A stream whose `session_id` was not opened with `OpenSession` fails with `NOT_FOUND` and the stream-scope error `unknown_session` (was: the stream created the session). Client: call `OpenSession` first.
- A stream message whose `model_id` is set and differs from its session's model ends the stream with the stream-scope error `malformed_payload` (was: the server ran the message's `model_id`). Client: leave `model_id` empty in stream messages, or send the session's model.
- A dropped stream closes its session with reason `disconnected`, and a stream-scope error closes it with reason `failed` (was: the session stayed open). Client: open a new session with a new `session_id` and send the unfinished tiles again.
- `CancelSession` closes the session, and its running stream ends before its next message or tile with the stream-scope error `cancelled` (was: the session was only marked cancelled, and its stream went on).
- The `session_id` of every closed session (by `CloseSession`, `CancelSession`, expiry, a dropped stream or a stream-scope error) stays reserved for `NXMNDR_SESSION_TTL_SECONDS` after it closed: `OpenSession` with it fails with `FAILED_PRECONDITION`, and `CloseSession` and `CancelSession` report the reason it closed (was: `CloseSession` and expiry removed the session, so `OpenSession` could open the ID again at once and a second `CloseSession` failed with `NOT_FOUND`; `OpenSession` with a cancelled ID returned that session with status `ok`). Client: give every session a new `session_id`.
- `OpenSession` with the `session_id` of an open session bound to another model fails with `ALREADY_EXISTS`; with the same model it returns that session (was: it returned the open session with status `ok`, whatever the spec). Client: use a new `session_id` for each model.
- A session idle longer than `NXMNDR_SESSION_TTL_SECONDS` (default 3600) is expired by a sweep that runs every 60 seconds from server start, and its model is unpinned (was: a session older than the TTL, counted from its creation and whether idle or not, was dropped when an `OpenSession` arrived, at most once a minute; a session pinned no model, and a later stream on the dropped ID created it again). A stream on an expired session ends with a stream-scope error (`error_code` `session_not_open`), and `CloseSession` reports status `expired`. A session with a running stream is never idle. Client: open a new session after a long pause, or raise the TTL.
- `OpenSession` refuses a `transport.chunk_bytes` above `Capabilities` `stream_max_chunk_bytes` (133169152, the gRPC message limit minus 1 MiB for the message's other fields) with `INVALID_ARGUMENT` (was: accepted, and a chunk of that size made the first full message exceed the gRPC message limit, which ended the stream with `RESOURCE_EXHAUSTED`). `NXMNDR_STREAM_MAX_CHUNK_BYTES` above that value is lowered to it, with a warning (was: used as given). Client: negotiate at most `stream_max_chunk_bytes`.
- `OpenSession` refuses a negative `transport.max_inflight` with `INVALID_ARGUMENT` and lowers a value above `NXMNDR_STREAM_MAX_INFLIGHT` (default 16) to it; 0 takes that value (was: any value was accepted and returned as the session's `max_inflight`, and 0 took the default). The server refuses to start (`ValueError`) when `NXMNDR_STREAM_MAX_INFLIGHT` is below 1 (was: accepted). Client: use the `max_inflight` that `OpenSession` returns. Operator: set the variable to 1 or more, or leave it unset (16).
- `OpenSession` refuses an `options.max_tile_bytes` that is not an integer, or is 0 or below, with `INVALID_ARGUMENT` (was: a value that was not an integer, or was empty, was ignored, and a value of 0 or below was accepted, so the session refused every non-empty tile as too large). Client: send a positive integer, or leave the option out.

SAM 3 prompts (`opt.sam_*` options, `nxmndr.models.sam`):
- `sam_input_points` is `[[x, y], ...]` and must come with `sam_input_labels`, `[1, 0, ...]` of the same length (1 positive, 0 negative) (was: a list of `[[[x, y]]]` entries, every label positive). Client: send both lists.
- All points and the box form one object prompt, which returns one mask (was: one mask per point, and a box ran as its 4 corner points, which gave 4 masks). Client: expect one mask per prompt.
- A malformed SAM option is refused; a stream tile fails with `malformed_options` (was: a logged warning, and the model ran without that prompt). Client: send valid JSON.
- A SAM prompt needs a `uint8` chip; a chip of another dtype is refused, and a stream tile fails with `malformed_payload` (was: cast with `astype("uint8")`). Client: convert native samples to 8-bit display values before sending.
- `is_sam_model` and `generate_grid_points` are removed (was: `is_sam_model` routed by the model's name, and `generate_grid_points` made a point grid). Client: read `capability.sam` from `LoadModelResponse.effective_metadata`, and send explicit points.

PyTorch models (generic `PYTORCH` specs, run in the PyTorch RPC worker):
- On a CUDA host the spawned worker builds every PyTorch model on the first GPU of the server's device plan (`cuda:0`) and applies the server's cuDNN policy (was: always on the CPU). The `device_id` and `device_type` metadata of a PyTorch `Predict` response or stream tile name the device that ran the model: for the spawned worker `cuda:0` and `gpu`, or `cpu` and `cpu` (was: the device plan entry picked for the call, such as `cpu:2`, which did not run the model). One inference call in the worker fails after 60 s (was 5 s). Operator: the worker's CUDA context and models use memory on `cuda:0` beside the server's own.
- A class registered with `register_pytorch_model` loads its weights file strictly, as catalog models do. Every failure of that load fails `LoadModel` and `OpenSession` with `INVALID_ARGUMENT` and a one-line message that says what is wrong: the file is missing; `torch.load` with `weights_only=True` refuses it; it is not a mapping of entry names, and the message gives its type or its first keys; it lacks one of the model's entries, has an entry the model does not have, or has a tensor of another shape, and the message names the first such entry (a checkpoint that nests the state dict under a key lacks every entry); or `load_state_dict` with `strict=True` fails for another reason, for example on a value that is not a tensor where the model has a tensor, and the message has the first reason torch gives. Values that are not tensors load when `load_state_dict` accepts them, such as the dict of `get_extra_state()` or the packed parameters of a quantized layer (was: `LoadModel` did not read the file, and the worker loaded it with `strict=False`, so entries the model does not have, such as a nested state dict, were ignored and the layers the file did not fill kept their random initial values). Embedder: save the full `state_dict()` of the registered class, not a checkpoint that wraps it.
- `serve`, when it returns, stops the PyTorch RPC worker after the model cache (was: the worker ran until the process exited). torch allows one RPC group per process, so once a server in a process has run generic PyTorch models, no other server in that process can load them; after the first server stops, the refusal says that they need a server in a new process. Embedder: start each server that serves PyTorch models in its own process.
- The server binds the rendezvous store of the PyTorch RPC group on `MASTER_ADDR` only, and an empty `MASTER_ADDR` means 127.0.0.1 (was: torch's store listened on every interface, whatever `MASTER_ADDR` named).
- After the spawned PyTorch RPC worker has exited, PyTorch `Predict` fails with `UNAVAILABLE` (metadata `error` `rpc_worker_not_available`), a new `StreamPredict` ends with a stream-scope error whose `error_code` is `internal` and whose `error` is `rpc_worker_not_available`, and PyTorch loads fail with a message that says to restart the server (was: `Predict`, a stream tile and `LoadModel` started a new worker process with the spec of the model they used). Operator: restart the server when its worker has exited.

Client (`nxmndr.client`):
- An `https://host[:port]` endpoint opens a TLS channel, default port 443 (was: the scheme was removed and the client dialed plaintext). Client: use `grpc://host:port`, `http://host:port` or `host:port` for a plaintext server.
- `http://host` without a port means port 80 (was: the scheme was removed and gRPC chose the port). Client: give the port.
- `InferenceGrpcClient` retries a unary call only when it fails with UNAVAILABLE (was: a call that failed with any status code, for example INVALID_ARGUMENT, NOT_FOUND, FAILED_PRECONDITION, DEADLINE_EXCEEDED or INTERNAL, was retried up to `max_attempts` times). A call that fails with INTERNAL or another server answer, or whose deadline passes, raises `InferenceGrpcError` after one attempt. Client: give slow calls (an `open_session` or `load_model` that downloads a model) a longer `timeout`, and retry a failed call yourself only where running it again is safe.
- An error no longer closes the client's channel (was: every failed call or stream closed it, which also ended every other call in progress on the same client). After a server outage gRPC reconnects the channel with an exponential backoff that grows to at most 120 s (gRPC's default), so after a long outage calls can fail with UNAVAILABLE for up to about two minutes after the server is back. Client: to reconnect at once, call `close()`, which closes the client's channel; the next call opens a new one. The new channel connects at once only if no other channel to the same endpoint (for example another `InferenceGrpcClient` for that endpoint) is open in the process, because gRPC shares one connection, and its backoff, between such channels.

### New features

Features that the previous version does not have, with the rules that clients and operators must follow. This is not a full list of new features.

Proxy:
- The proxy also forwards to OpenAI-platform endpoints: an endpoint whose `<PREFIX>_PROVIDER` is `openai`, or, when no provider is given, whose URL host is `api.openai.com`, with the key in `OPENAI_API_KEY`. For these it sends the configured deployment as `model` and replaces a `model` field from the client. Client: select the model with the deployment in the route.

Capabilities:
- `Capabilities` reports the largest stream values a session can negotiate: `stream_max_chunk_bytes` (133169152, the gRPC message limit minus 1 MiB for the message's other fields) and `stream_max_inflight` (`NXMNDR_STREAM_MAX_INFLIGHT`). Client: negotiate at most these values.
- `Capabilities` reports the PyTorch model catalog in `pytorch_model_classes` and `pytorch_model_input_sizes`. It leaves out both when the server cannot list its PyTorch model catalog, and `pytorch_model_input_sizes` leaves out a name whose input size cannot be read; both failures are logged on the server. Client: treat an absent entry as unknown, as for a server from before the entry.

Embedding the server (`nxmndr.server`):
- `create_server` starts a server without blocking, and `stop_server` stops it: gRPC first, then the model cache, then the PyTorch RPC worker. As for `serve`, once a server in a process has run generic PyTorch models, no other server in that process can load them. Embedder: start each server that serves PyTorch models in its own process.

PyTorch RPC worker on another host (`NXMNDR_RPC_EXTERNAL_WORKER=1`):
- External worker mode (`NXMNDR_RPC_EXTERNAL_WORKER=1`) uses a PyTorch RPC worker started by hand, on the server host or another host ([External Worker Mode](README.md#external-worker-mode-worker-on-another-host)). The RPC group listens on 127.0.0.1 unless `MASTER_ADDR` is set. Operator: for a worker on another host, set `MASTER_ADDR` to an address of the server host that the worker can reach, on a trusted network only.
- The external worker keeps its report connection to `MASTER_PORT + 1` open until it exits, and the server reads the connection closing as the worker's exit. After the worker exits, PyTorch `Predict` fails with `UNAVAILABLE` (metadata `error` `rpc_worker_not_available`), a new `StreamPredict` ends with a stream-scope error whose `error_code` is `internal` and whose `error` is `rpc_worker_not_available`, and loads fail naming the worker's pid and host, until the server restarts. Operator: run the same nxmndr version on the worker host as on the server.
- With a non-loopback `MASTER_ADDR`, `LoadModel` and `OpenSession` refuse a generic `PYTORCH` spec with uploaded `artifact` bytes with `FAILED_PRECONDITION`: the server saves the bytes on its own host, and a worker on another host can read them only through a shared filesystem. Client: send `source` with the weights path on the worker host.
- With a worker on another host, the model cache keys a `source` path by the size and modification time of the file on the server host, so a PyTorch weights file retrained in place on the worker host is served from the cached model until that model is evicted, or freed when every `LoadModel` caller has unloaded it and no session or call uses it; if the path also exists on the server host, the file there decides when the model loads again. Client: write retrained weights to a new path, or unload the model before you load it again.
